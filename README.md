# n8n-nodes-salvy

This is an n8n community node for the [Salvy](https://salvy.com.br) public API (v3). It lets you manage phone accounts, employees, cost centers, assets, asset statements and invoices from your n8n workflows.

[n8n](https://n8n.io/) is a [fair-code licensed](https://docs.n8n.io/sustainable-use-license/) workflow automation platform.

## Installation

Follow the [installation guide](https://docs.n8n.io/integrations/community-nodes/installation/) in the n8n community nodes documentation and install the package `@salvyltd/n8n-nodes-salvy`.

## Credentials

The node uses a **Salvy API** credential with a single field, **API Key**.

1. In the Salvy dashboard, create a company or organization API key ([API keys guide](https://docs.salvy.com.br/api-reference/v3/api-keys)).
2. In n8n, create a new **Salvy API** credential and paste the key.

The key is sent as `Authorization: Bearer <key>` to `https://api.salvy.com.br`. Sandbox and production keys use the same base URL; the key decides the environment ([environments](https://docs.salvy.com.br/api-reference/v3/environments)). n8n tests the credential with a read-only call to `GET /api/v3/companies`.

| Phone Account Group | Create, Delete, Get, Get Many, Update                                                                                                                                                                                 |
| Plan                | Get, Get Many                                                                                                                                                                                                         |
| Task                | Get, Get Results                                                                                                                                                                                                      |

Notes:

- **Get Many** operations return one item per record, with **Return All** / **Limit** handling the API's page-based pagination. With **Return All**, every page request carries the same filters and sort options as the first.
- **Download** operations return the file as binary data (field `data` by default).
- Simulate SMS and Simulate Signature are sandbox-only in the API; use them with a sandbox key.
- Batch operations (Batch Sync, Batch Update Cost Center) run in the background and return a task ID; poll it with **Task > Get** and **Task > Get Results**.
- The experimental WebRTC token endpoint is intentionally not included.

## Trigger

**Salvy Trigger** starts a workflow when Salvy sends a webhook event.

- Pick one or more **Events**; the list is loaded from `GET /api/v3/webhook-event-types`, so new event types show up without a node update.
- When the workflow is activated, the node registers its production webhook URL with `POST /api/v3/webhook-endpoints` and stores the endpoint ID and signing secret in the workflow's static data. Deactivating the workflow deletes the endpoint. If the stored endpoint was registered for a different URL or event list, it is replaced.
- Every delivery is verified with the [Standard Webhooks](https://www.standardwebhooks.com/) (Svix) signature scheme: HMAC-SHA256 over the raw body, constant-time comparison, any of several `v1` signatures accepted, and timestamps more than 5 minutes off rejected. Invalid deliveries get `401` and do not start the workflow.
- Each delivery produces one item: `{ type, timestamp, data }`.

Requirements:

- A **company** API key with the `webhook-endpoint:create`, `webhook-endpoint:read` and `webhook-endpoint:delete` scopes.
- Your n8n instance must be reachable from the internet over **HTTPS** (the API only accepts `https://` webhook URLs). Set `WEBHOOK_URL` if n8n runs behind a proxy.

## Compatibility

Built with `@n8n/node-cli` 0.52.2. Tested by loading the built node into n8n 2.43.4.

## Development

```bash
npm install
npm run spec:refresh   # download the latest OpenAPI spec from docs.salvy.com.br
npm run generate       # regenerate nodes/Salvy/Salvy.properties.generated.ts
npm run lint
npm run build
npm test               # build, then run the trigger's signature and webhook lifecycle tests
npm run dev            # run n8n locally with the node loaded
```

The node is declarative: `nodes/Salvy/Salvy.properties.generated.ts` holds every parameter and request mapping and is produced at build time from the vendored spec. The generator is a dev dependency only; the published package has no runtime dependencies. Operation names and English descriptions live in `scripts/salvy-operations.mjs` and `scripts/i18n/descriptions.en.json`; `npm run generate` fails if the spec gains an unmapped operation or an untranslated description.
